队列：先进先出

栈：先进后出
可以实现嵌套调用（递归调用）函数的正确返回

循环队列（整数取余运算实现）
队 空 条 件 ： head=tail 
队 满 条 件 ： (tail+1)%size=head 
队 列 长 度 ： (tail-head+size)%size 
循 环 队 列 的 优 点 ： 相 比 普 通 队 列 ， 此 时 入 队 和 出 队 操 作 都 不 需 要 移 动 队 列 中 的 其 他 元 素 。


## 一、为什么需要循环队列（假溢出）

队列：队尾 rear(tail) 插入、队头 front(head) 删除，FIFO。

顺序队列的 tail 只会单向前进。设数组大小 M=6，入队 6 个后 tail=6（越界）；此时出队 2 个元素：

```
索引    0     1     2     3     4     5
      [ ]   [ ]   [a₃]  [a₄]  [a₅]  [a₆]    head=2, tail=6
```

head 前面空了两格，但 tail 已顶到数组末尾无法再入队 —— **明明有空间却"溢出"，称为假溢出**。
根源：tail 不会回头。真溢出是数组确实满了。

## 二、核心思想

把数组在逻辑上首尾接成圆环，tail 走到末尾后回到 0，复用前面腾出的空位。靠**取模 `%`** 实现：

```
tail  = (tail  + 1) % M     # 入队，走到 M-1 自动回到 0
head  = (head  + 1) % M     # 出队同理
```

## 三、判空与判满的矛盾（必考）

约定 **head 指向队头元素，tail 指向队尾元素的下一个位置**，初始 head=tail=0：

- 判空：`head == tail`
- 但若填满 M 个元素，tail 绕一圈也回到 `0 == head` —— 两个条件冲突，无法区分

**三种解决方案：**

| 方案 | 判空 | 判满 | 可存元素数 |
|------|------|------|-----------|
| **① 牺牲一个存储单元**（考试默认） | `head == tail` | `(tail+1)%M == head` | **M − 1** ⚠️ |
| ② 增设计数器 count | `count == 0` | `count == M` | **M**（不浪费空间） |
| ③ 增设标志位 tag（1=刚入队，0=刚出队） | `head==tail && tag==0` | `head==tail && tag==1` | M |

队列长度（元素个数）通用公式：**`(tail - head + M) % M`**（加 M 防绕回后变负数）。

## 四、绕回过程图解（M=6，方案①）

```
操作          0     1     2     3     4     5    head  tail  个数
初始          ·     ·     ·     ·     ·     ·      0     0     0
入 a,b,c,d,e  a     b     c     d     e     ·      0     5     5  ← (5+1)%6=0=head → 已满
出 a,b        ·     ·     c     d     e     ·      2     5     3
入 f          ·     ·     c     d     e     f      2     0     4  ← tail 绕回 0
入 g          g     ·     c     d     e     f      2     1     5  ← (1+1)%6=2=head → 满
出 c          g     ·     ·     d     e     f      3     1     4
```

入队 e 时数组还有 0 号位空着却判满 —— 这就是"牺牲一个存储单元"的代价：**M=6 只能存 5 个**。
入队 g 时用到绕回后的 5、0 号位，彻底解决假溢出。

## 五、代码实现（方案①）

```python
class CircularQueue:
    def __init__(self, m):
        self.data = [None] * m
        self.head = 0          # 指向队头元素
        self.tail = 0          # 指向队尾元素的下一个位置
        self.m = m

    def is_empty(self):
        return self.head == self.tail

    def is_full(self):
        return (self.tail + 1) % self.m == self.head      # 判满★必须取模

    def enqueue(self, x):
        if self.is_full():
            raise Exception("队列满，无法入队")
        self.data[self.tail] = x
        self.tail = (self.tail + 1) % self.m

    def dequeue(self):
        if self.is_empty():
            raise Exception("队列空，无法出队")
        x = self.data[self.head]
        self.head = (self.head + 1) % self.m
        return x

    def size(self):
        return (self.tail - self.head + self.m) % self.m  # 加 m 防负数
```

**所有操作时间复杂度 O(1)**，这是循环队列的价值：链式队列也 O(1)，但要额外存指针、有内存分配开销。

## 六、易错点清单

1. **数组大小 M ≠ 可存个数**：少用一格方案答 **M−1**；带计数器方案答 **M**（软考最爱挖的坑）
2. 判满必须带 `% M`：写成 `tail + 1 == head` 在绕回场景会漏判
3. 求元素个数必须 `+M` 再取模，不能直接 `tail - head`
4. **看清题目约定**：有的教材 head 指向队头元素的前一个位置，约定不同则具体指针初值与移动时机不同，但判满公式 `(tail+1)%M==head` 与长度公式不变
5. 循环队列**不需要移动元素**（对比普通顺序队列出队要整体前移，O(n)）

## 七、三种队列对比

| | 顺序队列 | **循环队列** | 链式队列 |
|--|---------|-------------|---------|
| 假溢出 | ✗ 有 | **✓ 无** | ✓ 无 |
| 出队代价 | 需移动元素 O(n) | **只动指针 O(1)** | 只动指针 O(1) |
| 空间 | 静态预分配 | 静态预分配，高效 | 动态 + 额外指针 |
| 判满 | 简单 | 需特殊处理 | 一般不判 |
| 适用 | — | **容量已知、高性能场景** | 容量不定 |

## 八、应用

- 操作系统：就绪队列、打印机等待队列、消息队列
- 网络：TCP 滑动窗口、网卡收发包的 **ring buffer（环形缓冲区）**
- 生产者—消费者同步模型
- 图 BFS 广度优先遍历
- 音视频/串口环形缓冲，避免内存分配抖动
